# Техническое задание (ТЗ): MVP локального прокси-клиента для ChatGPT

## 1. Цель этапа (MVP)
Создание консольного Python-скрипта, который способен локально запустить браузер с использованием заранее подготовленного пользовательского профиля (с куками сессии), зайти на сайт `chatgpt.com`, отправить тестовый промпт, дождаться полной генерации ответа и вывести его в консоль. 

**Важно:** На данном этапе мы НЕ делаем API-сервер (FastAPI), НЕ используем Docker и НЕ делаем ротацию аккаунтов. Цель MVP — отработать надежное взаимодействие с DOM-деревом ChatGPT и обойти базовые проверки Cloudflare через `nodriver`.

## 2. Стек технологий
* **Язык:** Python 3.10+
* **Асинхронность:** `asyncio` (весь скрипт должен быть строго асинхронным).
* **Управление браузером:** Пакет `nodriver` (запрещено использовать `selenium`, `playwright` или `undetected-chromedriver`).
* **Логирование:** Пакет `loguru` (вместо стандартного `print`).

## 3. Входные данные (Предоставляются заказчиком)
Разработчику будет передана диреректория с прогретым профилем Google Chrome (например, папка `test_profile_user_data`), в которой уже выполнен вход в аккаунт ChatGPT Plus.

## 4. Архитектура и алгоритм работы скрипта

Скрипт (`main.py`) должен выполнять следующие шаги строго последовательно:

### Шаг 4.1. Инициализация и запуск браузера
* Запустить Chrome через `nodriver.start()`.
* **Окно должно быть видимым** (headless-режим отключен на этапе MVP для визуального контроля и отладки).
* В конфигурации необходимо жестко прописать путь к папке профиля через атрибут `user_data_dir`.

### Шаг 4.2. Переход и валидация сессии
* Загрузить URL: `https://chatgpt.com`.
* Установить динамическое ожидание загрузки базового интерфейса (до 15 секунд).
* **Проверка на разлогин:** Скрипт должен проверить, есть ли на экране кнопка "Log in" / "Sign up". Если она найдена — скрипт должен выдать критическую ошибку в лог: `[CRITICAL] Сессия недействительна или требуется ручной вход` и завершить работу.

### Шаг 4.3. Имитация человеческого ввода
* Найти поле ввода промпта (`textarea`). 
* **Требование к скрытности:** Запрещено использовать мгновенную вставку текста или инъекции через JavaScript (`element.value = "..."`).
* Реализовать асинхронную функцию `human_type(element, text)`. Она должна:
  1. Вызвать `await element.focus()`.
  2. Вводить текст посимвольно (`send_keys()`).
  3. Делать рандомную задержку между вводом каждого символа от `0.02` до `0.07` секунд.

### Шаг 4.4. Отправка и умное ожидание ответа (Самый сложный этап)
* Нажать Enter или кликнуть на кнопку отправки.
* **Требование к ожиданию:** Запрещено использовать жесткие таймауты (`await asyncio.sleep(30)`). Ожидание должно базироваться на состоянии DOM-дерева.
* Алгоритм опроса (Polling):
  1. Дождаться, пока начнется генерация (появление индикатора работы или кнопки «Stop generating» / черного квадратика вместо стрелки отправки).
  2. В цикле (с шагом ~0.5 сек) проверять состояние этой кнопки.
  3. Генерация считается завершенной, когда кнопка "Stop" исчезнет, а кнопка "Send" снова станет активной (или появится кнопка "Copy" под ответом).
  4. Предусмотреть общий таймаут на генерацию (например, 120 секунд). Если ответ не сгенерировался — выбросить `TimeoutError`.

### Шаг 4.5. Сбор данных
* Найти в DOM-дереве все блоки с ответами ассистента.
* Извлечь текст из **строго последнего** сообщения ассистента (так как на странице могут быть старые сообщения из истории чата).
* Вывести текст в консоль через `loguru.info()` и сохранить его в текстовый файл `result.txt`.
* Сделать паузу в 5 секунд и корректно закрыть браузер (`await browser.stop()`).

## 5. Требования к надежности кода (Для разработчика)

1. **Динамические селекторы:** Интерфейс ChatGPT часто меняется (A/B тесты). Нельзя жестко привязываться к длинным сгенерированным CSS-классам (вроде `.text-base.flex.items-center`). 
   * *Рекомендация:* Использовать поиск по атрибутам `data-testid` (например, `[data-testid="send-button"]`), ролям (`role="presentation"`) или специфичным ID, которые меняются реже.
2. **Обработка исключений:** Обернуть блоки поиска элементов в `try/except`. Если поле ввода не найдено за отведенное время, скрипт не должен падать с системным трейсбеком, он должен залогировать понятную ошибку: `[ERROR] Элемент textarea не найден на странице` и закрыть браузер.
3. **Чистота профиля:** Скрипт не должен изменять структуру переданной папки `User Data` или блокировать её (обязательно вызывать корректную остановку браузера в блоке `finally`).

## 6. Требуемый результат (Deliverables)

Разработчик должен сдать:
1. Файл `main.py` (чистый, прокомментированный код).
2. Файл `requirements.txt` с точными версиями библиотек (как минимум `nodriver` и `loguru`).
3. Короткий `README.md` с инструкцией, как подставить свою папку профиля и запустить скрипт.

Скрипт будет считаться успешным (MVP принят), если при локальном запуске заказчиком он без ошибок проведет диалог 5 раз подряд (запускаясь и закрываясь каждый раз) и корректно запишет 5 разных ответов в файл.
